# 临床智录：基于原文台账与来源校验的首次病程记录生成

版本日期：2026 年 11 月 5 日。当前为可运行的本地工程版本；真实指定 Qwen 服务尚未接入，真实模型效果和医学评分尚未测量。

## 1. 任务与设计目标

系统读取主办方提供、带资料截止点的入院资料，以指定模型生成“病例特点、拟诊讨论、诊疗计划”三段正文，以及关键依据和待核事项。设计优先保证事实来源清楚、协议完整、失败可追溯与流程可复现。针对赛题要求，将未提供信息、已知阴性、入院初步判断、推断边界及拟实施计划分开表达。

主要工程风险包括：数值或单位抄错、不同时间信息混合、把缺失写成正常、把初步判断升级为确诊、把计划写成已实施、引用来源编号存在但不支持结论，以及模型返回格式错误导致整批结果丢失。

## 2. 系统方法

流程为输入校验、原文台账、指定模型生成、结构与来源检查、事实一致性规则审计、结果及日志原子写入。当前默认每例一次调用，串行执行，不自动重试。

原文台账保存每个片段的完整原文、来源编号、数字集合与缺失/否定提示。它是额外的检查上下文，不替换原始资料，也不自行推断患者病情。模型同时读取原始 `sources`，避免结构抽取遗漏使事实丢失。

可选的双阶段方案先抽取逐字摘录，再生成正文。摘录必须在所引用的来源中连续原样出现；无依据摘录被拒绝，原文始终保留。可选修正仅按固定规则执行至多一次，共用每例调用预算，不进行多候选择优。是否启用取决于赛方预算和真实实验结果。

正式版本不启用外部 RAG，不读取开发数据或参考答案。未来如加入检索，需先登记赛方允许的资料，固定版本并评估时间和调用代价。

## 3. 提示词与输出控制

系统提示词约束病例原文仅作为数据，不执行其中嵌入的无关指令；以来源事实和截止点限制生成。病例特点保留重要阳性、已知阴性、数值单位及病程。拟诊讨论给出有依据的判断、针对性鉴别和信息不足。诊疗计划对应本例问题，使用拟、建议、复查等措辞并保留临床医生判断。

输出是严格五字段 JSON 对象，三段正文非空；依据说明标注真实 `source_ids`，并通过 `fact`/`inference` 区分事实与推断。待核事项覆盖资料缺失、冲突与待确认信息。只要求简短、可核对的结论与依据，不要求模型内部思维链。

提示词作为文本随源码提交；接口兼容性选项及固定参数记录在配置。默认温度为零，不发送服务未确认支持的种子或 JSON 模式，不能因此保证远程推理逐字确定。

## 4. 校验与异常处理

结构校验包括：病例编号、输入输出条数与顺序、三段类型与非空、依据结构、依据种类、来源属于当前病例、待核事项类型。模型接口响应和业务输出分离，避免直接将 HTTP 响应当作首程文件。

规则审计检查事实段中的新数字、常见指标与数值错配、事实依据中的数字与引用源不符、缺失误写为正常、部分否定翻转、计划误写为完成以及待核事项遗漏。规则是保守的风险信号，可能误报或漏报，不能证明临床结论正确。默认仅记录内容规则警告，不自动替换医学正文；结构或引用错误导致该例明确失败。

任务级输入错误返回退出码 2；单例失败保留原编号与错误，并继续下一例；所有病例处理完毕后将临时文件原子替换为正式输出。完整批处理允许部分失败并返回 0，任务级运行故障返回 1。正式评测应核对本次运行日志，不能把旧输出视为新结果。

## 5. 数据准备与防止泄漏

CMB-Clin 原始 74 例中文教学病例已下载，官方发布方声明 Apache-2.0。转换时仅使用描述，不输入标题或问答答案；参考资料另存，不随算法提交。保守时序词筛查后 22 例进入候选开发资料（16 开发、6 留出），52 例隔离待审。截止点是教学描述边界假设，不能冒充真实住院前瞻性数据。

MIMIC-IV Demo 2.2 开放数据包含 100 位去标识化患者，但不含自由文本病历。项目只下载四张结构化表，选取 85 位患者符合窗口的首次入院，按患者划分 68/17 例，共保留 2,719 条检验。保留条件同时约束采样时间与结果可用时间，排除未来结果。数据单独遵循 ODbL-1.0，保留来源与官方校验和。

另有 12 例人工合成边界样例与 1 例赛题示例。合成样例覆盖缺失、否定、数值、冲突、不同时间、单位、计划、提示注入及空资料，只用于工程测试，不作为医学专家审定样本。

## 6. 可复现性与日志

实现使用 Python 3.11 标准库，不要求第三方运行库、密钥、服务器或 GPU。统一入口在源码目录读取 `.env`、`input.json`，写入 `output.json` 和独立日志。不使用本机绝对路径、外部本地服务或交互输入。

日志记录运行 ID、输入输出哈希、代码/提示词/配置版本、病例对应、实际请求次数、每次请求起止时间、HTTP 状态、耗时和服务返回的 token 使用量。未返回的 token 量留空，不伪造估值。日志不保存原始患者资料或完整提示词请求正文。每次实验的运行目录保存对应代码与配置，支持重新核验。

算法打包只包含运行所需文件；排除真实配置、病例、参考答案、模拟接口及预生成输出。结果打包检查版本和哈希，拒绝将标为 MOCK 的工程模拟产物当作正式结果。

## 7. 已完成验证与实验计划

已在 Python 3.11.9 运行 66 项工程测试，覆盖协议、缺失配置、错误隔离、调用预算、HTTP 重试、结构修正、来源、数值与单位绑定、时间边界、数据校验及非医疗连通性检查。120 例（1 赛题示例、22 CMB 候选、85 MIMIC 结构化练习、12 合成样例）已通过本机回显模拟接口完成批处理，均产出符合协议的结果，实际记录 120 次请求。

这些是工程验证，不是 Qwen 性能或医学评分。当前无法报告真实拟诊准确性、计划充分性、相对基线提升或比赛预期名次。

真实接口可用后，按相同病例成对比较 baseline、grounded、extract_generate 和固定修正版，报告失败病例、来源/数值错误、耗时及调用代价；医学五维度由合适评审评价，未完成前不填造分数。改进版须用实际结果证明收益，也须报告规则误报、额外时延与未解决的问题。

## 8. 局限与后续衔接

规则只覆盖部分词法模式，不能识别全部医学幻觉、单位转换、复杂时序、隐含否定和结论支持关系。CMB 来源少且可能预训练污染，MIMIC 缺乏完整病史，开发评估不能替代赛方正式病例。提示词中的指令隔离也不是对提示注入的完整防护证明。

2026 年 11 月 4 日已检查官网公开赛题页、资料分类及公告附件，未找到实际 Qwen 配置。正式模型名称、版本、请求响应协议、调用/并发/重试预算和环境时限仍待赛方提供。当前数字是开发默认值，不能当作赛方规定。新增工具支持离线配置校验及一次不含病例的连通性请求。赛方正文的 `results.json` 与技术规范 `output.json` 打包口径需确认。队伍身份和签署声明由真实参赛人员补充；本地项目尚未向赛事系统提交。
