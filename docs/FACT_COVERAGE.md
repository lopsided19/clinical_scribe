# 时间、状态台账与遗漏检查

这一版在不增加默认模型调用次数的情况下，增加原文事实索引、时间/肯否状态检查、开发期关键事实覆盖评估，以及可重复生成的受控扰动集。正式输出仍是原有五字段病历对象；新增信息不塞入 `output.json`。

## 事实台账

运行时仅分析当前输入，不加载标注或参考答案。`src/facts.py` 提取常见检验指标、部分症状及缺失信息：

- `source_id`、`span`：定位未经改写的原文；偏移使用 Python Unicode 字符索引，不是 UTF-8 字节偏移。
- `entity/value/unit`：指标及数值、单位组合，数值不换算。
- `polarity`：阳性、阴性、缺失、不确定；词法模式覆盖有限，不代表完整自然语言理解。
- `duration`：可识别的邻接病程表述，例如“乏力 2 周”。
- `time_scope`：既往、入院、入院后、当前、未来或 unknown。
- `observation_time/available_time/cutoff_relation`：显式 ISO 时间及结果可用边界；只有采样时间早于截止点，不能证明结果已可用。未标时间、日期粒度不足或时区不兼容时保留 unknown。

例如“既往肌酐 90 μmol/L。入院时肌酐 185 μmol/L。”会形成两个带不同时间范围的事实。若正文将 90 写为入院结果，产生时间错配警告；不会自动把正文改成另一个数值。

完整原文只在输入 `case.sources` 中保留一份；模型上下文中的 `fact_ledger` 使用列名和行数组提供定位与状态，避免再复制一整份原文。这不等于保证每例 token 数都下降：额外元数据在短病例中仍可能增加长度，真实耗时和 token 代价待接口实测。

日志只增加台账版本、事实行数、字符数和哈希，不记录完整事实台账或原始请求正文。

## 内容审计

除了数值与单位校验，生成后还检查：

1. 既往/入院时间范围是否错用，明确日期是否冲突。
2. 仅被截止点后可用资料支持的事实是否进入病例特点或事实依据。
3. 肯定/否定状态是否与同一时间范围的来源不一致。
4. 同时点数值或肯否状态的潜在来源冲突是否在待核事项中提及。
5. 原文明确标记为异常、危急值或关键指标的候选事实是否在病例特点中出现。

时间范围、状态、冲突和遗漏等启发式结果主要用于人工复核；不能证明临床错误。单个无时间的不同数值不直接认定矛盾，不把不同日期或既往/入院值差异当作同一时点冲突。规则默认不改写医学正文，默认调用预算仍为每例 1 次。

## 独立的开发标注

自动候选事实不等于医学专家认定的关键事实。需要严谨评价时，开发人员或评审另行标注 `key_fact_id/kind/entity/source_ids/quote/fields`，并按需要指定数值、单位、状态、时间范围和病程。每条标注必须能回溯到指定来源的连续原文与对应事实，不能凭空添加、引用其他病例或使用明确在截止点后才可用的内容。

示例：

```json
{
  "schema_version": "1.0",
  "review_status": "engineering_only_not_clinician_validated",
  "cases": [{
    "case_id": "CONTROL-TIMELINE",
    "facts": [{
      "key_fact_id": "K1",
      "kind": "measurement",
      "entity": "肌酐",
      "value": "185",
      "unit": "μmol/L",
      "time_scope": "admission",
      "source_ids": ["S02"],
      "quote": "入院时肌酐 185 μmol/L，实验室标高。",
      "fields": ["case_features"]
    }]
  }]
}
```

用法：

```powershell
python tools/evaluate.py --input INPUT_PATH --output OUTPUT_PATH --log RUN_LOG_PATH --annotations data/synthetic/perturbations/coverage_annotations.json --report artifacts/coverage_metrics.json
```

标注文件可以覆盖当前评估的全部病例或一个子集。已标注病例失败、缺失或编号错配时，标注事实仍进入分母，覆盖数为零；分母为零时返回 null，不能显示 100%。未标注病例单独报告启发式候选，不混入标注覆盖率。字段匹配只作词法复核，不以出现关键词冒充医学充分性；同义表达可能漏匹配，条件句与复杂否定仍需人工判断。

标注仅由 `tools/evaluate.py` 显式读取。正式生成程序和算法 ZIP 不含这些病例标注及参考答案。

## 可重复的受控扰动

```powershell
python tools/perturb_cases.py
```

默认从 3 例项目人工构造的种子生成 19 例变体：删除检验结果、改数值、改单位、翻转否定、新增同一时间范围的冲突记录、移动时间范围/日期、把结果可用时间移到截止点之后。不适用的操作明确标注 `not_applicable`。输入文件不变；随机种子、母病例编号、操作名和前后哈希写入独立清单，变体仍遵守正式输入协议。

产物位于 `data/synthetic/perturbations/`：原始种子、变体输入、操作清单、工程覆盖标注与回归结果。单位扰动有意保留原数值以构造错误，不能解释为合法的医学单位转换。这些材料都是人工工程样例，不是真实患者病例或临床标准答案。

回归检查将母病例的旧回显与变体对照，确认每类故意制造的不一致能触发至少一个预期规则。19/19 表示这 19 个受控旧回显检查通过，不表示一般检测准确率、真实模型性能或医学安全性。完整模拟批处理现包含原有 120 例与新增 3 个种子、19 个变体，共 142 例。
