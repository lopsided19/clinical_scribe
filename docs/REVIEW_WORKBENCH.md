# 离线人工复核与实验对比

复核页面将原始资料、输出正文、依据、待核事项、规则提示及事实台账放在同一病例中。所有资源内嵌，不启动服务、不加载远程资源、不发送病例、不调用模型。它支持人工记录问题，不自动生成专家评分。

## 打开与生成

运行 `python tools/run_local_demo.py` 后，双击 `artifacts/local_demo_review.html`。这是明确标记的模拟回显演示，包含 142 例工程输入。真实实验工具也会为每次运行生成 `review.html`。

已有输入和输出时，可单独生成：

```powershell
python tools/review_report.py --input INPUT_PATH --output OUTPUT_PATH --log RUN_LOG_PATH --html artifacts/review.html
```

可加 `--annotations ANNOTATION_PATH` 显示独立标注覆盖与遗漏。未提供标注的病例只展示启发式候选；标注状态随页面展示。标注规则见 `FACT_COVERAGE.md`。

## 复核流程

1. 按病例编号搜索，或筛选有规则提示、失败/格式无效、有遗漏候选、尚未复核的病例。
2. 阅读原始资料与五字段输出。展开事实台账，核对时间、数值单位与肯否状态；点击来源编号返回对应原文。字符定位按 Python Unicode 索引解释。
3. 填写评审编号，选择“本次复核未发现问题”“发现问题，需修改”或“有争议，需进一步复核”，写明来源编号、生成句、具体问题及严重性。未看过的病例保持“尚未复核”。
4. 点击“导出复核意见”。下载文件包含全部病例，包含被筛选隐藏和未复核的病例；不附整份患者原文或病历正文。自由填写的意见可能含摘录，按原资料的要求保管。
5. 恢复工作时，打开同一批输入/输出生成的页面，导入意见文件。病例编号、数量、状态及输入输出内容哈希必须一致；无效文件整体拒绝。已有意见将被替换时先提示确认。每位评审分别导出，保留独立原始意见。

意见只在当前页面内存中保存，不自动写入浏览器存储。关闭、刷新、重新生成页面前请先导出。页面不修改 `output.json`，导出的意见不是修订后的正式输出，也不是赛方认可的评分。

复核文件的 `review_set_id` 绑定规范化 JSON 内容；文件缩进或键顺序变化不影响绑定，病例与输出内容变化会改变绑定。此哈希防止误配，不能验证评审身份或防止联合篡改。

## 已有实验的可信对比

```powershell
python tools/compare_runs.py --baseline BASELINE_RUN_DIR --candidate CANDIDATE_RUN_DIR --report artifacts/comparison.json
```

两个目录均须来自 `run_experiment.py` 的完整冻结运行，包含源码、完整实际配置、提示词、输入、输出与日志；仅拷贝三个结果 JSON 不足以对照。可附 `--annotations ANNOTATION_PATH`，对两种方法使用同一份独立标注。

对比工具不发请求，先验证文件哈希、逐例输入输出哈希、病例顺序、配置/提示词、调用数与耗时有效性；拒绝未完整结束的任务、MOCK 标识、不同输入文件、不同模型名或不同已记录接口地址。病例失败仍允许比较，标注事实继续进入分母。

报告列出逐例状态、格式、规则、覆盖、调用次数与耗时差值，以及配置、代码和提示词变化。只有双方均为有效成功输出时，才比较规则增加/解除；失败不算“解决了原有规则问题”。token 各字段分别披露已返回之和、返回次数与缺失次数，没有返回时为 null。耗时给出逐例中位数及最近秩 P95，包含失败病例。

模型名、接口地址和哈希只能验证记录的一致性，不能证明实际服务版本、调用授权、日志真实性或因果收益。配置变化、服务负载、模型随机性与小样本都影响解释；医学质量仍须独立复核。

## 验证范围

Python 测试覆盖文件/代码篡改、逐例哈希、失败分母、模型/接口/输入不同、部分 token、HTML 转义与脚本哈希。`node tests/review_ui.test.cjs` 用内存 DOM 桩检查筛选、进度、完整导出、导入验证与取消替换，共 10 项，不使用浏览器、网络或第三方包。

当前会话的浏览器安全策略禁止本地文件 URL，因此尚未完成实际浏览器兼容性和视觉验收。复核页的 CSP 禁止网络连接及外部资源；这些工程检查不能证明对所有浏览器、超大病例或复杂医学表达均正确。
