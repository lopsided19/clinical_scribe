# 真实模型实验与消融方案

状态：尚未获得赛方实际模型接口，以下为已实现的实验方案，未填造性能结果。

## 实验对象与冻结

先使用 CMB 开发集 16 例核查提示词及错误，再冻结方法、参数和代码，用 6 例留出集做一次最终开发评价。MIMIC 68/17 例分开报告，主要衡量结构与数值处理，不能和中文临床教学病例混成一个“医学准确率”。人工合成的 12 例用于边界与提示注入检查，单独报告。

CMB 留出并非赛方正式测试，公开数据还可能已被预训练模型看到；数据量较小，不能据此作稳定临床泛化结论。MOCK 遍历所有资料只验证接口、格式和批处理，不训练或测量模型。

每次真实实验固定实际模型名称、服务版本、数据 SHA-256、提示词版本、参数、超时、重试及预算；使用独立运行目录。除为检验服务随机性而预先规定的重复实验外，不为单病例重复挑选最好输出。不同方法在相同病例上进行成对比较。多调用方案额外披露调用成本，不能宣称其计算成本与一次调用相等。

## 方法矩阵

| 方法 | 原文 | 台账 | 提取调用 | 固定校验修正 | 调用预算 |
|---|---|---|---|---|---|
| baseline | 完整 | 无 | 无 | 无 | 每例 1 次 |
| grounded | 完整 | 有 | 无 | 无，规则只记录 | 每例 1 次 |
| extract_generate | 完整 | 有 | 先提取，逐字核验摘录 | 无 | 每例至少 2 次 |
| repair | 完整 | 有 | 无 | 结构/高风险规则命中后至多修正 1 次 | 配置最多 3 次，正常只需 1 次 |

`baseline` 与 `grounded` 使用相同医学约束提示词，差异是台账和生成后审计。因为默认审计不改写正文，不能把“发现错误”误写成“已提升生成质量”。修正版才可能改变最终文本，其收益须以最终输出与调用代价证明。

赛方调用预算不足时，不运行不符合规则的变体。请求失败和重试同样计入每例预算；默认不自动重试。生成参数是否支持种子、JSON 模式及最终协议须以赛方附件为准。

## 自动记录

- 病例条数与顺序、格式完整性、成功与失败例数、无效引用、数值规则命中。
- 实际每例调用次数、HTTP 状态、起止时间、耗时、服务返回的 token 使用量（未提供则留空，不估算伪装实测）。
- 原始输入、最终输出、代码、提示词和配置的哈希；模型实际名称。
- 数字集合精确率、覆盖率仅辅助检查：不能体现单位、指标绑定、时序、关键性或临床充分性。

## 人工医学评价

按 `CLINICAL_REVIEW.md` 为每例记录事实忠实性、拟诊分析、计划针对性、个体化、来源与待核事项。最好两位具备相关临床能力的评审独立评价，分歧复核；没有医学评审时如实标注“未开展”。评分权重及分值由赛方确定，本项目不自创一个分数冒充官方分数。

主要错误类型：关键事实编造、数值/单位/时间错配、否定翻转、未提供写成正常、初步判断写成确诊、计划写成已实施、诊疗计划严重遗漏、来源不支持结论、遗漏关键待核事项。

比较时报告每种错误例数、差值、失败病例和调用代价；合并失败病例进入分母，不能只挑成功案例。样本量很小，优先提供逐例配对表与区间，不对微小差异下强结论。
